# 보기 버튼과 Mac 단일보기 스크롤 수정

2026-09-12 · ADF 0.3.26 Mac 빌드에 포함하는 변경. 공개 릴리즈 갱신은 별도 작업이다.

## 보기 버튼

PDF를 처음 열었을 때 실제 기본 모드는 `continuous`이고, 체크된 버튼도 한 쪽 연속 보기 하나였다. 그러나 공통 테마가 체크와 키보드 포커스에 같은 배경색을 사용해, 포커스를 받은 한 쪽씩 보기 버튼까지 선택된 것처럼 보였다.

- 문서를 연 직후 포커스를 PDF 뷰어에 둔다.
- 보기 모드 버튼을 배타적인 `QButtonGroup`으로 묶는다. 배치 취소 등으로 보기 변경을 거절하면 실제 보기 모드에 맞춰 선택을 복원한다.
- 선택/누름은 채운 배경, 키보드 포커스는 얇은 테두리로 구분한다. 테두리 공간과 패딩을 함께 조정해 버튼 크기를 유지한다.
- 같은 공통 테마를 사용하는 도구 버튼과 펜·지우개 옵션에도 이 구분을 적용한다.

## 한 쪽씩 / 두 쪽씩 보기의 휠

기존 처리는 페이지 경계에서 크기가 1인 입력에도 페이지를 넘겼다. 트랙패드의 연속 입력이나 관성이 들어오면 각 이벤트가 다음 페이지를 열어 문서 끝까지 이동했다.

- 일반 마우스는 각도 입력을 한 칸(120)까지 모아 한 페이지/묶음씩 넘긴다.
- 정밀 스크롤은 픽셀 입력을 우선 사용한다. 페이지 경계에서 48px를 모으면 한 번 넘기고, 같은 제스처의 나머지 입력으로는 다시 넘기지 않는다.
- 관성만으로 새 페이지를 넘기지 않는다. 제스처 단계 정보가 없는 정밀 장치는 250ms 입력 공백으로 다음 동작을 구분한다.
- 확대 상태에서는 현재 페이지 안에서 픽셀 거리만큼 스크롤한다. 다음 페이지는 위쪽, 이전 페이지는 아래쪽에서 이어 본다.
- macOS의 일반 마우스에도 추정 픽셀 값이 들어올 수 있으므로 정밀 스크롤 장치 기능과 제스처 단계로 구분한다.
- 수평 입력, 자연스러운 스크롤 방향, 첫/마지막 페이지 경계, 입력량이 0인 확대 이벤트를 처리한다.

## 확인

- 수정 전 실패하던 페이지 넘김과 버튼 배경 재현 검사를 추가했다.
- `tests/test_reader_input.py`: offscreen에서 24개 통과. 한 쪽씩, 두 쪽씩, 첫 페이지 오른쪽 배치를 각각 검사한다.
- macOS Cocoa에서 위 24개와 `tests/test_ui.py`의 포커스/도구 표시/기존 단일·마주보기 휠 검사 4개: **28개 통과, 하위 검사 2개 통과**.
- 보기 버튼과 펜·지우개의 포커스 검사는 offscreen에서도 각각 통과했다. Space 키로 실행되고 포커스 테두리 때문에 버튼 크기가 달라지지 않는지 확인했다.
- Cocoa 소스 실행 화면에서 문서를 연 직후 뷰어에 포커스가 있고 `continuous`만 체크된 것을 확인했다. 버튼 배경과 테두리는 실제 위젯 캡처로 확인했다.
- 기존 UI·필기·렌더링·전체 화면·로딩·페이지 번호 관련 검사도 수행했다. Windows 전용 항목은 이 Mac에서 실행하지 않았다.

이 검증은 소스 실행과 합성 `QWheelEvent` 입력 기준이다. 사용자의 실제 마우스/트랙패드 감도와 설치 앱 동작 검증을 대신하지 않는다.
