# XDF 0.3.46 한글(HWPX) 변환 검증

검증일: 2026년 10월 14일 (한국시간).

PDF를 한글(HWPX)로 바꿀 때 원본의 줄바꿈·들여쓰기·줄 간격·글꼴·문단 여백·표·캡션이 한글에서 같은 자리에 그려지도록 변환기를 다시 만들었습니다. 변환기는 `adf/pdf2hwpx/` 폴더 하나로 독립해 다른 프로젝트에서도 쓸 수 있고, 사용법과 측정한 한글 규칙은 [README](../adf/pdf2hwpx/README.md)에 정리했습니다.

## 바뀐 점

- **글줄 위치를 PDF 글줄마다 측정합니다.** PDF의 글줄마다 한글 렌더에서 같은 모양의 줄이 같은 높이에서 같은 곳에서 시작해 같은 곳에서 끝나는지 비교합니다. 끝점이 같으면 같은 단어까지 한 줄에 들어간 것이라 줄바꿈 충실도를 잽니다.
- **한글이 실제로 그리는 글자 폭을 모델로 씁니다.** 설치된 글꼴의 글자 폭과 한컴 HFT 글꼴 265종의 폭을 한글에서 직접 재서 저장했고, 없는 글자의 대체 폭과 띄어쓰기가 줄어드는 한도, 이탤릭 글자 폭, 탭 위치까지 맞춥니다. 이 폭으로 자간을 정해 한글이 PDF와 같은 곳에서 줄을 바꾸게 합니다.
- **문단 구조를 다시 만듭니다.** 들여쓰기·내어쓰기·글머리표(한글 번호·기호 포함)·목차 점선과 쪽 번호·밑줄·형광펜·위 첨자·기호 글꼴 글자를 복원하고, 디자인 쪽은 조각마다 글상자로, 2단 쪽은 단으로 둡니다.
- **표와 캡션.** 선이 있는 표는 병합·열 너비·행 높이·테두리·배경색을 반영합니다. "표 1.", "<그림 2>", "Table 3:"으로 시작하는 줄은 표·그림에 붙은 한글의 진짜 캡션으로 넣어 표를 옮기면 함께 움직입니다. 선이 없고 글자만 열로 정렬된 표(논문의 3선 표, 정렬만 된 표)도 편집 가능한 표로 읽습니다.
- **모든 문서가 끝까지 변환됩니다.** 잘못 읽힌 표 격자는 범위 안으로 정리하고, 한글이 담지 못하는 표는 그 영역을 그림으로, 구조를 읽지 못한 쪽은 쪽 그림(경고 표시)으로 넣습니다.

## 한글 렌더 검사

한컴 한글을 COM으로 실행해 변환한 쪽을 이미지로 렌더링하고 원본 PDF와 줄마다 대조합니다 (`scripts/pdf2hwpx/layout_check.py`).

- 보고서·서식·사진 대지·디자인 문서·2단 영문·표 등 14종 46쪽은 모두 원본과 같은 쪽 수로 열리고, 글줄 1784개 중 1612개(90%)가 같은 위치·같은 줄바꿈으로 그려집니다. 개발에 쓰지 않은 문서 6종(과업내용서·회의록·공고문·윤리 가이드라인·제안요청서·영문 논문)도 따로 검증했습니다.
- 선 없는 표를 넣은 합성 문서 2쪽은 인식을 끄면 표 0개에 92%(213/232줄), 켜면 편집 가능한 표 2개에 96%(222/232줄)입니다.
- 선 없는 표 인식은 이 PC의 PDF 99개에서 줄이 어긋난 86쪽을 쪽마다 따로 변환해 끄고 켠 결과를 비교했습니다. 글줄 5373개 중 제자리에 그려진 줄이 끈 상태 4080개(75.9%)에서 켠 상태 4188개(77.9%)로 늘었습니다. 쪽별로는 21쪽 개선, 14쪽 악화, 51쪽 동일입니다. 처음 구현은 오히려 217줄이 줄어 그 원인(행 경계가 칸 안 둘째 줄을 가르는 것, 2열 목록·목차·디자인 카드를 표로 읽는 것)을 고친 뒤의 결과입니다.
- 표와 그림 위·아래 캡션의 간격을 한글이 그리는 높이에 맞춰 12개 사례에서 위치를 확인했습니다.

## 견고성

이 PC의 PDF 99개(보고서·제안서·공고문·회의록·논문·디자인 시안, 1661쪽, 문서당 앞 40쪽)를 모두 변환했습니다. 오류 0건, 쪽 그림으로 대체한 쪽 0쪽, 표 1720개이며 쪽당 중간 0.76초입니다.

## 검사

- Windows 개발 PC에서 전체 소스 검사 **669개**와 세부 검사 166개가 통과했고, 선택 의존성·환경에 따른 검사 8개는 건너뛰었습니다. 변환기 전용 검사는 글자 폭 모델, 줄바꿈 맞춤, 쪽 구성, 캡션 24개, 선 없는 표 7개, 독립 실행(폴더만 복사해 변환), 글꼴 처리 등입니다.
- 버전 표기(앱·설치 프로그램·안내 문서)를 0.3.46으로 맞췄습니다.

## 한계

모든 PDF를 원본과 100% 동일한 편집 가능한 한글 문서로 변환한다고 보장하지 않습니다.

- 글꼴 파일을 포함하지 않으므로 해당 PC에 없는 글꼴은 대체되며, 이때 글자 폭이 달라 줄바꿈이 어긋납니다. 남은 차이의 대부분이 이 경우입니다.
- 선 없는 표 인식은 포스터처럼 큼직한 제목과 작은 본문이 열로 정렬된 쪽을 표로 잘못 읽을 수 있습니다(86쪽 중 1쪽, −9줄). 표 안에서 줄이 여러 개인 행은 한글이 몇 pt 더 높게 그려 아래 글이 조금 밀릴 수 있습니다.
- 스캔한 PDF는 글자가 없어 AI 변환이 필요합니다. 수식·회전한 글자·유니코드 대응이 없는 기호는 그림으로 들어가 편집할 수 없고, 자유 배치 쪽의 도형·선도 그림입니다.
- 한글 렌더 검사는 한컴 한글이 설치된 Windows PC에서 한 것입니다. macOS의 한컴 한글에서는 확인하지 않았습니다.

## 2026년 10월 15일 로고·작업 취소 보완

- 제공된 전체 로고와 작은 화면용 심볼을 독립된 SVG 원본으로 적용했습니다. 앱 시작 화면·홈페이지에는 전체 로고를, 앱·트레이·탐색기·설치 화면·파비콘에는 심볼을 사용합니다. 원래 도형·비례·주홍색 `#F04B2D`·투명 배경을 보존합니다. 아이콘을 다시 생성해도 두 원본이 바뀌지 않는 것을 확인했습니다.
- 한컴 글꼴이 없는 빌드 PC에서도 한컴 자체 글꼴 이름을 유지합니다. 결과를 여는 한컴 한글에서 사용할 글꼴을 변환 PC의 설치 여부만으로 바꾸지 않습니다.
- 초기 배포 빌드에서 작업 취소 검사가 실패했습니다. Windows 프로세스 스냅샷의 부모 ID가 재사용되면 오래된 다른 프로세스를 기다릴 수 있어 생성 시각으로 자식을 구분합니다. 부모가 먼저 종료되면 보관한 작업 프로세스 핸들로 자식을 종료하고 파일 핸들이 해제될 때까지 기다립니다.
- 수정 전 코드에서 재현 검사가 시간 초과로 실패하는 것을 확인했습니다. 수정 후 작업 프로세스 검사 10개가 통과했고, 실제 PDF 분할 취소와 재사용된 부모 ID·먼저 종료되는 부모를 재현하는 검사를 각각 10회, 총 20회 통과했습니다. 관계없는 이전 프로세스와 형제 프로세스가 계속 실행되는지도 확인했습니다.
- 로컬 Windows 11 Home 26200의 네이티브 구성 요소 검사 16,276개가 통과했습니다. 실제 탐색기 메뉴 조합 검사는 실패했으며, 설치되어 있던 0.3.45에서도 같은 실패를 재현했습니다. 구성 요소 검사 통과와 실제 탐색기 통합은 구분합니다.
- 홈페이지 다섯 페이지를 1440px·390px에서 확인했습니다. 새 로고·파비콘이 로드되고 가로 넘침이 없으며, Windows 0.3.46과 macOS 0.3.45의 다운로드 링크를 구분합니다. Mac은 기존 Developer ID 서명·공증된 0.3.45를 제공합니다.
- 배포 패키지의 소스 대조 검사에서 한글 변환기의 명령행 진입점이 빠진 것을 발견해, 변환기 모듈 16개를 모두 명시적으로 수집하도록 패키징 설정을 수정했습니다. 소스 검사 통과와 실제 패키지의 모듈 대조는 별도로 확인합니다.

## Windows 배포 빌드 검증

빌드 원본은 `b71ce12ad515970505ffd6fbe985b07e3250e699`이며 [GitHub Actions 빌드](https://github.com/Keilkim/ADF/actions/runs/38681050824)가 성공했습니다.

- Windows Server 2022에서 소스·OCR 검사 **661개**, 세부 검사 **174개**가 통과했고, 선택 의존성·환경에 따른 검사 17개는 건너뛰었습니다.
- 네이티브 구성 요소 검사 **16,276개**가 통과했습니다. 실제 탐색기 메뉴 조합 검사는 실패했으며 빌드 원본 기록의 `explorer_menu_check`에 그대로 남겼습니다.
- 격리 설치·설치된 파일 **1,147개**의 해시 대조·설치 앱 기능·PDF 작업 프로세스·독립 병합/분할 창·제거가 통과했습니다. 기존 설치·연결·업데이트 보관함을 보존하는지도 확인했습니다.
- 대응 소스 **768개**, 동결 모듈 **72개**, 리소스 **589개**를 대조했습니다. OCR 모델 5개·검색 모델 파일 2개·외부 라이브러리 원본 소스 38개와 배포 파일 해시를 확인했습니다.
- 최근 Windows 버전과 달라진 파일이 697MiB 이상으로 부분 패치 기준을 넘어서, 이번에는 전체 설치 파일로 업데이트합니다. 생성된 부분 패치는 없으며, 부분 패치 검사는 해당 대상이 없어 건너뛰었습니다.

설치 파일과 대응 소스·외부 소스·빌드 원본·배포 앱 HWPX 검사 결과·SHA-256은 [0.3.46 릴리즈](https://github.com/Keilkim/ADF/releases/tag/v0.3.46)에서 제공합니다. Windows 파일은 미서명이며 실행이 차단되거나 경고가 표시될 수 있습니다. macOS는 기존 서명·공증된 0.3.45를 제공합니다.

## Windows 11의 배포 파일 업그레이드 확인

- 릴리즈 초안에 업로드한 파일 8개와 SHA-256 목록 7개를 대조했고, 설치 파일·대응 소스·외부 소스·파일 목록이 성공한 빌드의 해시와 일치했습니다. [배포 자산 준비 및 HWPX 검사](https://github.com/Keilkim/ADF/actions/runs/38682428136)도 성공했습니다.
- 공개 0.3.45 파일 목록으로 로컬 설치 파일 1,145개의 해시를 확인한 뒤, 해당 배포 파일만 격리된 임시 설치 폴더로 복사했습니다. 실제 설치본의 제거 프로그램·등록 정보는 복사하지 않았습니다.
- 최종 0.3.46 설치 파일로 이 폴더를 업그레이드하고, 파일 1,147개가 새 배포 목록의 크기·해시와 일치하는지 확인했습니다. 실행 파일과 탐색기 DLL의 버전이 0.3.46이며, 두 파일 각각에 새 심볼 프레임 9개가 들어 있음을 확인했습니다. PNG·ICO·ICNS·SVG 리소스 6종도 원본과 일치했습니다.
- 설치된 탐색기 DLL의 구성 요소, 앱 내부 기능, 독립 병합·분할 창 4개 경로, 편집 가능한 HWPX의 셀별 글꼴·크기·굵기·색·행·열·테두리 및 공개판의 Gemini 키 미포함 검사가 통과했습니다.
- 격리 설치 제거가 통과했고, 실제 사용 중인 0.3.45 실행 파일의 해시가 전후 동일한 것을 확인했습니다. 위 탐색기 메뉴 조합·실제 입력 장치·인쇄 조작의 검증 한계는 별도로 유지합니다.
