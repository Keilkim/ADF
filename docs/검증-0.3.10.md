# ADF 0.3.10 클립보드 오류 수정 검증

2026-09-09, Windows x64 / Python 3.12 / PyMuPDF 1.28.2.

## 원인과 수정

- 설치본 0.3.8의 오류 기록에서 이미지 적용 2회와 클립보드 페이지 추가 1회가 모두 `_snapshot()`의 `Document.save()`에서 `code=8: invalid key in dict`로 실패했다.
- 최근 문서 중 15페이지 PDF에서도 같은 오류를 재현했다. 사용되지 않는 잘못된 PDF 사전 객체를 기본 저장이 읽으면서 실패했다. 문서 내용은 외부로 전송하지 않았다.
- 0.3.9 소스에 들어 있던 `garbage=1` 설정을 회귀 검사로 검증했다. 실행 취소 사본, 작업 전달용 바이트, 저장·내보내기 사본에서 사용하지 않는 객체를 제외한다. 살아 있는 페이지·이미지 객체 번호를 유지해야 하므로 번호까지 재배치하는 단계로 올리지 않는다. [PyMuPDF 저장 옵션](https://pymupdf.readthedocs.io/en/latest/document.html#Document.save)
- 추가로 압축 함수가 PDF 바이트 입력의 크기를 구할 때 기본 저장을 호출해 같은 오류가 나는 경로를 수정했다. 원본 바이트 길이를 직접 사용하며, 문서 직렬화가 필요한 대체 경로에도 `garbage=1`을 적용했다.

## 자동 검사

- 독립 빌드 폴더에서 전체 Python 검사 **171개, 하위 검사 96개 통과**.
- 새 PDF 직렬화 회귀 검사 9개: 실제 잘못된 사전 객체가 들어 있는 합성 PDF로 원래 오류 재현, 클립보드 페이지·이미지 삽입, 회전·삭제·재정렬, 실패 시 복구, 실행 취소·다시 실행, 저장·분리·병합·압축, 원본 보존.
- 기존 설정으로 되돌리면 클립보드 회귀 검사가 원래 오류로 실패함을 확인했다. 객체 번호를 재배치하는 설정으로 바꾸면 선택된 이미지·페이지 번호 보존 검사가 실패한다.
- 새 UI 검사 2개: 이미지·텍스트 편집 뒤 페이지 사이의 + 메뉴로 클립보드 이미지 추가, PDF·이미지 파일 클립보드 추가. 위치·순서·실행 취소·다시 실행·저장 후 재열기·투명 배경을 검사한다.
- 로컬 실제 PDF **7개, 총 76페이지**로 앞·중간·끝 클립보드 삽입, 저장 결과의 기존 페이지 픽셀·텍스트·객체 번호, 이미지 적용·삭제, 페이지 편집, 혼합 파일 삽입, 바이트 입력 압축, 분리를 검사했다. 원본 파일 해시는 모두 유지되었다. 임시 결과 문서는 검사 후 삭제한다.
- 탐색기 확장 빌드 및 네이티브 통합 검사 **49,543개 assertion 통과**.

## 빌드 구분

같은 작업 폴더에서 도장 화면 개편이 별도 진행 중임을 확인했다. 이 수정본은 기존 0.3.9 소스 묶음에 이번 수정·회귀 검사·버전 정보를 반영한 `.tools/clipboard-fix-build`에서 검사·제작한다. 동시 편집 중인 도장 화면 변경은 이 설치 파일에 포함하지 않는다.

배포 EXE를 포함한 설치 파일을 임시 폴더·전용 레지스트리 영역에 실제로 설치했다. 설치된 EXE의 PDF 렌더링, 내장 글꼴 편집·저장, 본문 직접 입력, 페이지 번호, 이미지 페이지 추가, 회전, 작업 프로세스의 병합·분리·압축, 독립 도구 창, 네이티브 탐색기 선택 처리가 통과했다. 제거와 임시 영역 정리도 완료했으며, 기존 설치본과 PDF 기본 연결은 유지되었다.

설치본의 기본 smoke 검사는 이미지 파일을 통한 페이지 삽입을 검사한다. 클립보드와 잘못된 PDF 객체의 상세 검사는 동일 소스의 Python UI·문서 회귀 검사 및 실제 문서 검사로 수행했다.

최종 파일은 `release/clipboard-fix-0.3.10/ADF-Setup-0.3.10.exe`이며, 해당 폴더에 대응 소스·외부 라이브러리 원본·해시·검증 기록을 함께 둔다. 검증 로그 원본은 `.tools/clipboard-fix-build/.tools/verification`에 있다.
