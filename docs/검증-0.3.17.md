# ADF 0.3.17 로컬 OCR · Markdown과 실제 진행 표시

2026-09-09 Windows x64.

## 변경 사항

- OCR · MD 버튼과 파일 메뉴에서 전체·현재·선택·직접 입력 페이지를 내보낸다. 한글·영어 OCR, PP-DocLayoutV3의 영역·읽는 순서, SLANet Plus 표 구조 모델을 ONNX Runtime CPU로 실행한다. 모델 5개를 배포처 SHA-256으로 확인해 설치 파일에 포함한다. 사용 중 모델 다운로드나 문서 업로드가 필요 없다.
- 자동 모드는 PDF 텍스트를 우선 사용하고 부족한 영역에 OCR을 수행한다. 모든 글자를 다시 인식하는 옵션도 제공한다. 문단과 표는 Markdown, 병합 셀은 HTML 표, 이미지·그래프·도형은 PNG와 본문 링크로 저장한다. 전체 페이지 이미지, 영역·읽는 순서 JSON, 변환 결과와 확인 항목도 저장한다.
- 현재 문서의 선택 페이지를 한 페이지씩 준비하므로 저장 전 편집 내용도 포함한다. 별도 프로세스에서 인식하며 취소·Esc로 중단한다. 임시 묶음을 만들고 완료 시 같은 볼륨의 새 폴더로 한 번에 옮긴다. 취소·오류에서는 결과 폴더를 생성하지 않으며 기존 폴더를 덮어쓰지 않는다. PDF 복사 권한을 확인한다.
- PDF 열기의 파일 읽기·구조·페이지·첫 화면 준비를 별도 프로세스로 옮겼다. 원본 파일의 읽은 바이트와 페이지 수를 표시하고 취소할 수 있다. 초기 페이지 크기를 캐시해 화면과 미리보기가 PDF 전체를 반복 조회하지 않도록 했다. 편집 후에는 해당 캐시를 무효화한다.
- 진행률은 실제 바이트·확인한 페이지·준비한 모델·변환 완료 페이지에 따라 표시한다. 시간을 기준으로 임의 증가시키지 않는다. OCR 추론 내부의 완료 비율은 계산할 수 없으므로 스피너와 단계명, 별도로 완료한 페이지 수를 표시한다.

## 검증 범위와 한계

- 실제 한글 스캔 샘플에서 OCR 텍스트, 두 단 읽는 순서, 표의 숫자·행·열, 그래프·흐름도 이미지와 MD 링크를 검사한다. 소켓 연결을 차단한 테스트로 모델이 준비된 상태에서 오프라인 변환을 확인한다.
- 실제 작업 프로세스에서 수정한 PDF의 내보내기 이미지가 현재 문서와 같은지 비교한다. OCR 추론 중 Esc 취소, 프로세스 종료, 임시 폴더 정리와 결과 미생성을 확인한다.
- 파일 열기의 실제 바이트·페이지 진척, 시간 경과만으로 진행률이 오르지 않는 동작, 암호와 복사 제한, 취소 시 기존 문서와 미저장 편집 보존, 회전 후 페이지 크기 캐시를 확인한다.
- 악의적인 PDF 텍스트가 HTML 스크립트나 Markdown 외부 이미지로 해석되지 않도록 이스케이프하며, 병합 셀의 표 구조는 보존한다. 기존 출력 폴더와 누락된 이미지 링크는 저장 전에 거부한다.

OCR은 모든 문서에서 완벽한 결과를 보장하지 않는다. 흐린 스캔·작은 글자·복잡한 표·읽는 방향 등에 따라 오인식·구조 누락이 생길 수 있다. 그래프와 도형은 원본의 그림을 보존하며 데이터나 편집 가능한 도형으로 재생성하지 않는다. 인식 확신도가 높더라도 틀릴 수 있으므로 확인용 원본도 제공한다.

Docling/PyTorch 평가에서는 Windows Application Control이 torch_python.dll을 차단했다. 해당 실행 환경은 최종 제품에 포함하지 않고, 실제 실행과 인식이 확인된 ONNX 엔진을 사용한다. 네이티브 탐색기 테스트의 기존 실행 제한과 최종 설치·실행 검사 결과, 배포 용량은 `release/배포상태-0.3.17.md`에 기록한다.
