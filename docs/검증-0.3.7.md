# ADF 0.3.7 검증 기록

2026-09-09, Windows x64 / Python 3.12.

- `python -m pytest tests -q`: **144개 및 하위 검사 82개 통과**. 여섯 페이지의 왼쪽/오른쪽 시작, 빈 문서·한 장·홀수 페이지, 첫 장/끝 장 빈칸, 두 쪽씩/연속 전환, 휠 이동과 확대 시 경계 스크롤을 포함한다. 페이지 번호의 좌우 여백·실제 PDF 저장·미리보기 일치도 검사했다.
- 설치 글꼴 검사는 무관한 파일명 속 내부 영문·한글·PostScript 이름, 보통체/굵은체 구분, 기존 가족/스타일 이름과 타이포그래픽 이름의 차이, TTC 두 번째 글꼴의 선택·PDF 저장, 실행 중 목록 갱신, 손상 파일 건너뛰기를 포함한다. Windows 글꼴 등록은 변경하지 않는다.
- 이 PC에서 이전에 찾지 못했던 `ArialMT`, `Arial-BoldMT`가 각각 Arial Regular, Arial Bold로 해결되는 것을 확인했다. 모든 가변 글꼴 인스턴스나 앱 전용 글꼴에 대한 지원을 의미하지 않는다.
- 기존 글꼴 검사 PDF는 페이지별 생성 시각 차이로 별개 글꼴 리소스가 될 수 있었다. 두 페이지가 같은 글꼴 바이트를 공유하도록 재현 자료를 고정한 뒤 전체 검사를 통과했다.
- 실제 Windows Qt 소스 화면을 1100px 폭에서 확인했다. 왼쪽 시작 `[1 | 2]`, 오른쪽 시작 `[빈칸 | 1]`, 마지막 `[6 | 빈칸]`, 두 쪽 연속 보기를 캡처했으며 보기 아이콘과 확대 컨트롤이 창 안에 맞는다. 번호 미리보기에서도 첫 장 오른쪽 배치와 빈칸의 버튼 숨김을 확인했다.
- `python main.py --smoke-test .tools/source-smoke-0.3.7.json`: 전체 항목 통과. PDF 렌더링, 내장 글꼴 편집·저장, 문단 입력, 번호 대칭·자릿수, 페이지 삽입·회전과 마지막 일괄 저장을 검사했다.
- `scripts/build-shell.ps1 -SkipTests`: 네이티브 DLL과 테스트 프로그램 컴파일 성공. 기존 라이브러리 버전과 캐시의 외부 소스 8개 SHA-256이 매니페스트와 일치한다.
- 기존 Windows Application Control 제한으로 배포 EXE·설치·제거·탐색기 DLL의 실행은 검증하지 않았다. 컴파일/소스 실행과 배포 실행 검증을 구분한다. 기존 설치와 PDF 기본 연결은 변경하지 않았다. macOS 빌드는 이 환경에서 검증하지 않았다.

이름 검색은 가족·스타일·전체·PostScript 이름 필드를 사용한다. [Microsoft OpenType name 명세](https://learn.microsoft.com/en-us/typography/opentype/spec/name)의 ID 1/2/4/6/16/17/21/22와 [fontTools TTFont](https://fonttools.readthedocs.io/en/latest/ttLib/ttFont.html)의 컬렉션 `fontNumber`를 참고했다.
